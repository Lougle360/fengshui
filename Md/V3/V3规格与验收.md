# V3 AI 全自动白话释读版：规格与验收

## 总目标

将 V2 的 36 本风水及术数书籍制作成普通中文读者能够顺畅阅读、专业人士能够核对原文、所有解释均可追溯的 AI 全自动白话释读版。

V3 是完整释读版，不是摘要、节选、改编或学术定本。V2 和源 PDF 保持只读不变。

## 内容规则

1. 古文改写为通俗、完整的现代汉语；日文翻译为现代中文。
2. 已经是现代汉语的段落只做必要整理，不为了变化而改写。
3. 专业术语、流派名、干支、卦名、爻位、方位、度数、数字、公式、口诀、书名和人名不得擅改。
4. 专业术语保留原词；只有术语表批准的解释可以作为确定释义。含义未定的古籍专名必须作为原词引用，不得拆字猜释或擅自认定人物、流派、神名和现代概念。
5. 口诀、赋、经文和真言保留原文，再逐句解释；符咒不猜译。
6. 不增加原书没有的结论，不替作者纠正理论，不把不同流派强行统一。
7. OCR 可疑、原义多解或模型无法可靠判断的内容，采用保守释读并进入复核台账。

## 输出结构

- V3 根目录只放完整通过一书覆盖检查的 36 个 Markdown。
- 未完成书稿只放在 `_drafts`，不冒充成品。
- 每个白话块带稳定的 `V3_SOURCE_ID`，并附可展开的对应原文。
- 图片复制到 V3 的 `assets`，使用相对路径。
- 模型中间结果和断点放在 `_work`。
- 验收、状态、术语和不确定项放在 `_reports`。

## 分层核义与断点

37,151 个待处理块先由写作模型处理。本地硬规则先拦截术语、保护值、含混专名、原文复制和白话化不足等确定性问题，并允许最多三轮强模型修复；通过硬规则后，再由独立模型核对原文与候选稿。核义模型只判错、不直接改稿；语义异议只自动修复一次，仍有争议就保守保留并进入复核台账，避免反复改写造成语义漂移。核义重点包括：漏译、增译、反义、术语误换、数字变化、干支或卦象变化、方位变化、日文误译，以及把推测写成事实。

来源 ID 使用“书号 + 原始块序号 + 分片序号 + 原文 SHA-256 前缀”的内容寻址格式。只有 ID、完整原文哈希和完整原文同时匹配的结果才可复用或渲染；目录识别、断行合并等切分规则变化后，旧的顺序编号结果不得直接套用。

每次成功 API 响应按“模型 + 系统规则 + 请求正文”生成内容哈希缓存。相同请求重跑直接使用缓存，token 记为 0；批次后续失败不重复已成功调用。网络失败、异常 JSON 和多余结果项分别进入 API 台账，密钥不进入缓存、脚本、报告、日志或命令参数。

费用按接口返回的普通输入、缓存命中输入和输出 token 分别计价。模型返回 HTTP 成功但 JSON 不合格时，也必须先计入费用再重试；费用估算超过人民币 150 元立即停止。

模型不确定不等于流程失败；不确定项必须显式标注并完整进入 `V3待人工复核台账.jsonl`。静默猜写属于失败。

- 每个白话块均有原文追溯标记和对应原文。
- 日文书正文全部完成中文翻译。
- 所有低置信和争议项完整入账。
- V2 的 8,777 张图片引用全部保留；缺图和绝对路径均为 0。
- 锁定术语、保护值、未引用含混专名、无依据定义、整段原文重复和白话化不足等本地硬错误均为 0。
- 6 个已知源损坏页继续单独说明，不伪造恢复。

仅创建目录、复制 V2、生成空文件、完成部分书籍或通过局部抽查，都不能称为 V3 完成。
