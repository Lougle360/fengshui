# V3 多供应商加速方案

更新时间：2026-09-23

## 目标

在不丢失断点、不重复成功片段、不泄露密钥、总费用仍受人民币 150 元硬上限约束的前提下，把 V3 的预计工期由 6—10 天压缩到 2—4 天；供应商数量、稳定并发和批处理能力足够时，争取 36—72 小时。

## 已完成的底层改造

- 同一个逻辑模型可配置一家或多家 OpenAI 兼容 API。
- 片段按请求内容的 SHA-256 固定分片；同一片段重跑仍选择同一路由。
- 每家供应商、每个远程模型使用独立并发池，不再被单一全局网关锁住。
- 默认硅基流动的历史缓存键完全保持不变；已有成功响应不会失效或重复计费。
- 非默认供应商的缓存包含非敏感路由身份，避免跨供应商响应冲突。
- 密钥只从指定环境变量或隐藏输入读取；路由文件禁止包含密钥值。
- 费用同时记入总账和供应商分账；自定义供应商必须配置输入、输出单价，否则拒绝启动。
- 支持流式和非流式 OpenAI 兼容响应，并可按供应商删除不支持的请求字段。
- 2026-09-23 离线回归测试：26/26 通过。

## 推荐执行方式

1. 当前硅基流动后台进程继续运行，不为改代码而中断。
2. 收集用户已有供应商名称、可用模型和账户并发额度；密钥不在聊天中明文发送。
3. 每家只跑同一组代表性小样，测吞吐、超时率、JSON 合格率、初稿硬错误率和真实单价。
4. 淘汰慢、贵或质量差的路由；只把通过门槛的路由加入正式分片。
5. 优先让快速低价模型承担初稿；高质量模型集中处理本地硬错误和语义修复；独立模型负责核义。
6. 如果供应商支持异步 Batch，优先将大批初稿或独立核义放入 Batch；实时 API 负责修复和补漏。
7. 切换前先冻结当前进度和费用快照；新进程只从未完成片段恢复。

## 验收门槛

- 已成功片段不得重新付费。
- 任何密钥不得出现在配置、日志、缓存、命令行或报告中。
- 全局估算费用不得突破人民币 150 元。
- 新路由的小样质量不得低于当前硅基流动基准。
- 每个结果仍须保留稳定片段 ID、原文 SHA-256、模型裁决和不确定项。

## 需要的非敏感信息

只需要供应商名称、接口是否 OpenAI 兼容、可用模型名称、官方单价和大致并发额度。密钥随后通过环境变量或隐藏输入配置。
