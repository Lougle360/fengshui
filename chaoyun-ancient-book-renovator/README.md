# 超云古书翻新 Skill：把难懂的古书，变成普通人读得懂的书

你交给它一本难辨认、难理解的古书 PDF，它按照一套编辑流程，将其整理成尽量忠实原意、解释清楚、阅读顺畅的现代白话书。

比如，一本繁体竖排的风水古籍，里面既有模糊字，又有文言文和专业术语。最终要交给读者的，不只是“识别出来的文字”，而是一份有本书介绍、有白话正文、有图表说明、有术语解释的完整读物。

> 版本说明：当前版本为 workflow 1.10。继承此前的底本证据、疑点裁决、过程版保留、三轮全书审读、两轮稳定和候选出版校验，新增“完整阅读单元＋注释归属＋成稿位置绑定”。正文与古注都译为白话，读者通过版面层级理解它们的关系。程序校验不代替真实阅读。

### 1.10 怎样复用《郭璞葬经》的成书方法

先核实全书正文、古注和跨页续文的关系，再按完整单元翻译和排版。原文无注允许保留；篇注、总注、注中注按实际解释范围登记；底本缺文如实保留说明，不能补造正文来满足配对。

六个相关 Skill 已明确交接职责。新增阅读单元校验同时接入批量翻译前的生产计划和两道出版闸门；只改版本号或刷新哈希不能得到新的验收。旧书 PDF 不随 Skill 更新自动改写。

## 一、它和普通 PDF 转文字，有什么不同？

可以把两者理解为“抄书”和“整理出版一本书”的区别。

| 普通 PDF 转文字 | 超云古书翻新 |
|---|---|
| 把图片中的文字识别出来 | 先识别，再检查错字、漏字和阅读顺序 |
| 将繁体转成简体 | 进一步把文言文、日文解释成现代中文 |
| 术语原样保留 | 解释术语在本书中的含义，帮助读者理解 |
| 导出文件即结束 | 检查全书内容、阅读体验和实际 PDF |
| 出错后不容易追查 | 保留原书位置、修改依据和疑点记录 |

它的目标不是让文字“看起来现代”，而是让读者真正理解：这段在说什么，为什么这么说，与前后内容有什么关系。

## 二、Skill 到底是什么？

你可以把 Skill 理解为一套供 AI 执行的“标准工作手册”。

它告诉 AI：

- 遇到什么书，先检查哪些问题。
- 每一步应该怎么处理。
- 发现疑点时，如何查证和修改。
- 做到什么程度，才算可以交付。

它不是装好后就能保证所有古书一次转好的万能软件。复杂任务仍需要识别工具、模型、排版工具，以及实际复核。

## 三、你需要提供什么？

最重要的是原书 PDF，再说明两件事：

1. 给谁看？例如：没有古文基础的风水爱好者。
2. 希望做成什么？例如：完整现代白话版，而不是摘要或节选。

其他信息也可以一起提供：作者、整理者、出品单位，以及是否允许使用付费识别或模型服务。

可以这样下任务（署名和出品单位按实际项目替换）：

```text
使用 $chaoyun-ancient-book-renovator，处理这本古书 PDF。
面向没有古文基础的风水爱好者，制作完整、普通人可以直接阅读的现代白话版，不做摘要代替全文。
保留必要原图，补充本书介绍、阅读引导和术语解释，术语表放在书末。
作者后另起一行写“葛超云 整理”，出品单位为“壮五福国学院”。
最终交付内容一致的 Markdown 和正式 PDF。
先选代表性章节试做并复核，通过后再处理全书；不能确定的内容如实保留，不编造。
```

## 四、它是怎样把古书变成白话书的？

当前结构是：一个总控 Skill，加八个子 Skill。

可以把它看成一个分工明确的编辑团队。这些是工作职责划分，不等于天然就有九个人独立审核。

| 角色 | 用大白话解释它的工作 |
|---|---|
| 总控 | 安排流程、检查每一步是否合格，决定能不能进入下一步 |
| PDF 诊断 | 先看这本书有多少页、清不清楚、怎么排版、难在哪里 |
| 原书重建 | 把文字和图表按正确顺序整理出来，并记住原书出处 |
| 疑点裁决 | 专门处理看不清、解释不通、前后矛盾等问题 |
| 文字规范 | 处理繁简字、异体字、标点和分段 |
| 白话转换 | 把古文或日文转成忠实原意的现代中文 |
| 阅读编辑 | 补齐介绍、阅读引导、术语解释等读者需要的内容 |
| 读者审编 | 从头到尾读一遍，检查普通人会在哪里卡住，做好增删改整 |
| 审核出版 | 核对内容与成品，检查目录、图片、排版和最终交付文件 |

实际执行时，先做代表性章节的小规模试验，再决定是否扩展到全书。发现问题就回到对应环节修正，不能一路导出文件就宣布完成。信息完整的导读／过程稿会保留用于审核；正式交付前再生成不含流程噪音的最终读者稿，并对这份最终稿重新通读。

## 五、“从读者视角增删改整”具体怎么做？

这是这套 Skill 中非常重要的一步。

**增：补上理解所必需的东西。**

例如，第一次出现“来龙”，不能只换成简体字。要说明它在本书中的具体意思、指向什么对象，以及读者容易误解的地方。新增解释必须与原文观点区分，不能假装是作者原话。

**删：减少妨碍阅读的杂物。**

例如重复的说明、识别残留、内部审核编号。不因为某段难懂，就把原书的重要内容删掉；原始材料和处理记录仍保留。

**改：把话真正说清楚。**

不是简单替换几个古字，而是理清一句话的主语、条件、因果和结论。同时保留原文的否定、限制和不确定性，不能越改越绝对。

**整：让全书容易顺着读。**

统一术语和标题，整理段落关系，必要时增加小标题与过渡说明。调整阅读结构时，仍保留与原书的对应关系。

判断标准是：读者不需要反复猜测，也能理解这段内容。

## 六、看不懂、看不清的地方，怎么办？

不是让 AI 猜一个答案，而是进入统一的“疑点账本”。

处理过程是：

发现问题 → 记录原书位置 → 查证 → 修改相关内容 → 再次复核 → 确认关闭或继续保留。

第一轮、第二轮，甚至第五轮发现的问题，都进入同一本账本，不会每轮另起一份，把旧问题忘掉。

这里要区分两个概念：

- 问题解决了：有依据、改到了正文，并且复核过。
- 记录消失了：只是删掉了问题，没有证明它被解决。

这套流程要求前者。已经解决的疑点仍保留历史；无法查明的内容不能硬说确定，影响关键理解的问题没有解决，就不能当作正式完成版交付。

## 七、最后你会拿到什么？

读者主要使用两份文件：

- 现代白话版 Markdown：可以继续修改的文字底稿。
- 正式 PDF：适合直接阅读、分享或打印的成品。

另外保留一套不打扰读者阅读的核查材料，包括原书对应关系、疑点账本、导读／过程稿和审核记录。过程稿可以很完整，但不能因为它对编辑有用，就把九项字段、审核语言和重复说明全部塞进正式读者版。

读者版应有完整的正文、合适的本书介绍、必要的图表说明，以及解释充分的书末术语表；正式 PDF 还要检查封面、版权页、目录跳转等。

正文改了，PDF 也必须重新生成和复核，不能交付两份内容不同的“最终版”。

## 八、它能保证任何古书都处理好吗？

不能。

缺页、严重模糊、无法辨认的字迹，不会因为流程完整就自动恢复。没有依据的内容不能补成作者原意。

workflow 1.8 已加入更严格的疑点处理、代表章节试验、全书读者审编、过程版／读者版分流和出版检查。但要注意：检查程序通过，只能证明相应检查通过；不等于整本书的解释已经百分之百正确。实际质量仍要通过具体书稿的逐段核对和全文阅读来验证。

尤其是风水类书籍，应该解释清楚作者和传统体系的观点，不把这些观点直接包装成现代科学结论。

超云古书翻新 Skill 最重要的价值，不是“快速生成一份 PDF”，而是：

**在保留原书依据的前提下，把古书整理成现代读者能够读进去、理解清楚，而且遇到疑问可以追溯的书。**

## 技术概览

把扫描版古书 PDF 翻新成现代人可以直接阅读的高质量 Markdown 与正式 PDF。

它不是简单的 OCR 工具，而是一套面向复杂古书的完整出版工作流：先保存原书证据，再恢复文字与版面，随后完成繁简转换、古文或日文今译、普通读者编辑、术语解释、质量审计和正式出版。

## 适合处理什么

- 扫描版、影印版和图片型 PDF
- 繁体中文、文言文、日文、汉文训读或多语言混排
- 竖排、多栏、夹注、眉批、图版、表格等复杂版式
- 需要转换成现代白话文、但又不能丢失原文依据的古书
- 需要封面、版权页、跳转目录、PDF 书签和正式书名的出版型成品

普通的数字版 PDF 如果只需要提取文字，不必使用这套重型流程。

## 最终产物

标准工作空间会保留两层内容：

1. **证据层**：原 PDF、页面图像、忠实转录、版面位置、置信度、疑难记录和来源追踪。
2. **阅读层**：现代标点、简体规范、现代白话文、编者导读、章节说明、图解、术语表、Markdown 和正式 PDF。

当目标是“普通人可以直接阅读”时，默认生成现代白话读者版，并要求：

- 原 PDF 每一页都有明确去向，不以样章冒充全书；
- 专业术语首次出现时解释，书末保留完整术语表；
- 古代风水、医学、术数或吉凶判断使用“书中认为”“传统上认为”等历史归属表达；
- 正式 PDF 包含封面、版权页、作者与整理者、出品方、可点击目录和 PDF 书签；
- 成品使用 `<原书名>·<版本名>.pdf`，只保留一个明确的正式交付文件。

阅读编辑始终采用“增、删、改、整”：增加真正解除理解障碍的背景、例子和过渡；从连续阅读路径中删去重复与流程噪音但不删除原书证据；把古奥表达改成自然现代中文而不改变原意；按照读者问题整理章节、概念和术语，同时另行保存原书次序。介绍必须完整回答读者为何读、读什么、怎样读和有哪些限制；核心术语必须有通俗解释、本书语境、准确出处、例子、关联概念与易混点，并通过独立读者审读。

## 质量等级

- **A — 可正式出版**：所有质量门通过，没有当前有效的实质未决疑点。
- **B — 可直接阅读，保留台账**：存在范围明确、不会破坏整体阅读的疑难项。
- **C — 辅助草稿**：仍有重要版式、识别或翻译风险，不得标成完整版。
- **D — 无法可靠恢复**：现有证据不足以负责任地完成转换。

样章只能验证技术路线，不能证明全书已经完成。扫描型古书达到 A/B 级前，必须完成逐页视觉证据覆盖或为每个无法处理的页面记录明确原因。

## 验证

### 文字硬检查：乾误作干、版心混入、流程用语

缺陷库（2026-09）在已交付的书里找到三类读者一眼就能看出的错误，而原有质量门都没有拦住：

- 繁简转换把八卦方位的“乾”改成“干”，例如《入地眼全书》中的“干龙”“干宫”“干峰”；
- 版心文字混进正文，例如“入地眼全书卷五砂法八李辰砂法”“青囊海角经卷一”；
- 读者稿出现“OCR识别错误”“乱码”“无法进行有效释读”等内部用语。

`scripts/text_hygiene.py` 逐块对照 `20-source`，检查“乾”是否被转成方位义的“干”；同时扫描读者稿中非标题行的“书名＋卷次”，以及 `book.json` `running_header_patterns` 声明的刻工名、馆藏印记，还有流程用语。`validate_workspace.py` 在 normalized 及以后各阶段自动执行该检查，`audit_publication.py` 在发布时再查一次。用例见 `scripts/test_text_hygiene.py`。旧书不会自动改写，重新校验时会如实报出这些问题。

### 版本 1.8：过程版保留与最终读者版收口

- 完整导读、术语字段、审核记录和编辑推理可以保留在导读／过程稿中，但它不是默认正式读者版。
- 最终读者稿采用 `compact_final_reader`，清除字段堆叠、流程语言、重复脚手架和没有解决真实阅读障碍的 AI 自写内容。
- AI 生成的介绍、过渡、术语解释、例子、图注和阅读说明逐项检查读者需要、通俗程度、来源依据和阅读负担。
- 全书审读覆盖每个章节及前后附属内容；循环次数不是合格证，退出条件是问题闭环、最终稿重新通读、内容绑定和 PDF 门禁全部通过。
- `reader-acceptance-report.json` 保留过程稿快照，并记录六项最终收口检查；正式出版只接受已经验收的最终读者稿。

### 版本 1.6：疑点从发现到成书验收

- 所有环节发现疑点先登记、定位、保存输入版本，再分派给负责环节；完整账本不删除。
- 已确认、误报、非正文、结构问题都必须有可定位证据及文件摘要，不能只改“已解决”。
- 修正必须在快照之间精确重放并落到当前文件；检查原文、译文、术语、正文、图示、出版六个影响范围。
- 重复疑点必须关联主疑点，主疑点未解决则不能借“重复”清零；重开保留原疑点编号。
- 关闭前要求独立复核执行记录；发布前再按最终书稿逐项核对，未决问题须如实披露。
- 全书扩展前先做真实代表章节试验，记录修正、残留、新增错误、耗时和费用。缺少试验或最终复核记录会阻止发布。

新增命令：`project_open_items.py <workspace> --pilot`（只读试验门）和 `project_open_items.py <workspace> --check --publication`（疑点发布门）。详见疑点子 Skill 的 `references/closure-and-trial.md`。旧关闭结论迁移时重新列为待核实，不能自动升级通过。

这些校验验证证据文件和处理记录，不能自动证明判断正确、复核者确实独立，或已发现所有问题。自动测试使用合成数据，不是已经完成的实书试验。

### 继承的 1.5 能力：成果、工作流、审核三层闭环

- **成果**：每本书单独约定读者问题、预期理解与对应章节；原文、白话、成书段落和图解保留逐项复核证据。
- **工作流**：组装全部文字 → 全书审编与忠实性审核 → 冻结 → 候选 PDF → 校样审核 → 正式发布。旧正式 PDF 在候选失败时不变，通过替换前先备份。
- **审核**：显式选择交付模式，不再靠读者名称猜测；实际核对原 PDF 页数和摘要，拒绝空原文、空译文。PDF 比较保留标点、负号和额外文字，不再以字符顺序包含作为一致性证明。
- **返工**：源文、译文、术语、导读、排版分别有影响范围；上游文件变化使绑定的审核失效，不能仅刷新摘要继续交付。
- **辅助脚本**：自动生成待审的内容映射、文件摘要和逐页校样，不自动填写语义或视觉“通过”。

详见总控 Skill 的 `references/delivery-and-rework.md`。新规则不会自动为旧书补齐审核证据；真实章节与全书阅读基准仍需另行执行。

### 继承的 1.4 能力

- 介绍、术语解释必须实际出现在对应书稿位置，不能仅存在于 JSON 报告。
- 每次修改保留输入/输出快照，程序按文字位置重放修改；各轮未结项持续结转。
- 全文按章节/小节记录读者问题、通俗回答、前置知识、理解证据；全部核心术语复核。
- 生产和复核保留独立执行记录，不能只填两个不同名字。
- 验收稿、出版 Markdown、图片和 PDF 绑定摘要；每页校样图必须对应实际 PDF，并有真实视觉检查记录。
- 原有工作空间不会自动升级为“通过”。保留历史、重新审读；这次升级不会修改现有书稿。

程序验证的是文件一致性、覆盖范围与记录闭环，不等于读者理解或翻译准确。真实章节与整本书的语义验收仍需实际执行，不能用合成自测冒充。

## 设计原则

- 不用流畅改写覆盖原始证据。
- 不根据上下文虚构缺失文字。
- 不把技术检查通过等同于语义正确。
- 不把模型提出的每一条疑问都当成正文缺损；候选、裁决历史和读者可见未决项必须分开。
- 不把样章、局部结果或 C 级草稿标为完整版。
- 付费全书处理前先估算成本并取得明确授权。
- 所有现代化内容都应能追溯到稳定的原书页面和内容块。
