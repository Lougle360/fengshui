# 人工意见录入表

这张表用来记录**您本人**（或其他人工审读者）发现的问题。录入后会和 AI 工作记录合并，重算《缺陷库统计报告》的结论，并找出哪些问题只有人能发现。

## 怎么填

- **最少只填四栏**：书、位置、问题描述、您的判断。其余栏可以留空，我会按分类表补全，并请您确认。
- 一个问题一行。同一个问题在多处出现，写一行，在“位置”里列出几处或写“全书多处”。
- 有截图的，把图片放进 `缺陷库/人工截图/` 文件夹，文件名写在“截图”栏，例如 `003-p45-版心.png`。
- 不确定属于哪一类，就不填“类别”，只把现象写清楚。
- 填完告诉我，我运行 `python tools/import_human.py` 把它转成 `human-defects.jsonl`（格式与 `defects.jsonl` 相同，`source_type` 为 `human`）。

## 优先补的几件事

AI 工作记录里有几次重大返工，只记了结果、没记原因。这些最需要您的意见：

1. **《平砂玉尺经》1.5 版被退回的原因。** 质量报告评了 B 级，记录里没写您为什么不接受。
2. **《青囊海角经》B 级成品后两次整体重建的原因。** 是读者定位不对、翻译质量不够，还是别的？
3. **《郭璞葬经》旧 PDF 撤销的经过。** 记录显示是“旧注没进正文”，请确认是否还有其他原因。
4. **《入地眼全书》《郭璞葬经》目前的验收状态。** 交付总账停在 09-26，没有写后来的结论。
5. **您读成品时最常皱眉的地方。** 例如某一页、某一段，哪怕只是“读不下去”，也值得记下来。

## 各栏说明

| 栏目 | 填什么 | 对应 `defects.jsonl` 字段 |
|---|---|---|
| 编号 | H001、H002……依次编 | `defect_id` |
| 书 | 编号加书名，如 `002 入地眼全书` | `book` |
| 版本 | 看的是哪个版本；不清楚就写“当前版” | `version` |
| 位置 | PDF 页码、章节名或引一句原话，能让人找到即可 | `location` |
| 问题描述 | 用自己的话写现象 | `description` |
| 原文 | 古书原文（可不填） | `before` |
| 现在的写法 | 成品里现在怎么写的（可不填） | `after`（当前） |
| 应该怎么改 | 您认为正确的写法（可不填） | `after`（建议） |
| 类别 | 从下面“类别”表里选一个；可不填 | `category` |
| 严重程度 | 影响原意 / 影响阅读 / 仅外观；可不填 | `severity` |
| 您的判断 | 必须改 / 最好改 / 可以接受 / 退回 | `outcome` |
| 截图 | `人工截图/` 里的文件名 | `evidence` |

以下字段由我补，您不用填：`caused_at`（产生环节）、`found_at`（固定为“人工审读”）、`rework_cost`（返工代价）、`subcategory`（子类）、`source_type`（固定为 `human`）。

### 类别

| 类别 | 指什么 | 例子 |
|---|---|---|
| 识别 | 古书原文的字认错、漏字、多字 | “宋末文”被认成“朱未之” |
| 结构 | 页序、跨页接续、版心页眉混入正文 | “玉尺经下 卷之四”被当成正文 |
| 归属 | 经文和注文分错，注文对不上经句 | 一句经文被并进注文 |
| 范围 | 该收的内容没收，或收了不该收的 | 古注没进完整白话版 |
| 忠实性 | 白话意思和原文不符：误译、漏译、乱加内容 | “以水为护卫”译成“不属于以水为护卫” |
| 释读缺口 | 该解释的没解释，写成“具体所指不详” | “元女”（玄女）被写成所指不详 |
| 术语 | 风水术语解释错、解释不够或前后不一致 | “绝命”“天医”被当成未知词 |
| 读者层 | 意思对，但普通读者读不懂或读着累 | 同一句说明重复二十多次 |
| 出版 | PDF 排版、目录、页码、图片等问题 | |
| 质量门失效 | 评级通过，但您认为不合格 | 1.5 版评 B 级被退回 |
| 工具缺陷 | 脚本或流程本身出错 | 字形改对了却写不回稿子 |
| 流程噪音 | 不是问题却被当问题登记，或内部流程文字印进成品 | 书里出现“核义模型仍建议修订” |

## AI 记录与人工意见对照

这一节在您录入意见后由我填写，用来回答三个问题：

1. **AI 已经发现、人也发现的问题**：说明 AI 的检查找到了问题，但没有拦住。重点看它为什么没拦住。
2. **只有人发现的问题**：AI 的检查完全漏掉了。这些要补成新的检查项或样例。
3. **AI 当作问题、人认为可以接受的问题**：AI 过度登记。这些要从检查里减掉，避免噪音。

| 对照结果 | 条数 | 典型例子 | 对 Skill 的改进建议 |
|---|---|---|---|
| AI 与人都发现 | 待填 | 待填 | 待填 |
| 只有人发现 | 待填 | 待填 | 待填 |
| AI 登记、人认为可接受 | 待填 | 待填 | 待填 |
| AI 判为误报、人认为是问题 | 待填 | 待填 | 待填 |

对照方法：按书和位置把人工意见和 `defects.jsonl` 逐条匹配；位置对不上的，再按原文或现象描述的关键词查找。匹配结果会写进 `work/human-vs-ai.jsonl`，每条都附双方的编号，方便回查。
